# BCU オンライン対戦（UDP対応・開発テスト版 / protocol v7）

## ダウンロード

配布用ZIPは [pvp-dev Release](https://github.com/SSSCFW/BCU-java-PC/releases/tag/pvp-dev) の
`bcu-pvp-portable.zip` です。[直接ダウンロード](https://github.com/SSSCFW/BCU-java-PC/releases/download/pvp-dev/bcu-pvp-portable.zip)できます。
隣の `bcu-pvp-portable.zip.sha256` でSHA-256を確認できます。開発版なので更新されます。
Actionsの `bcu-pvp-portable` もフォルダーの中身を保存する方式に変更し、ZIP内の二重ZIPをなくしています。
Release版には `bcu-pvp-portable/` フォルダーがあり、Actions版は展開先直下に本体が並びます。

**今回の通信はv7です。旧v6以前とは互換性がないため、両プレイヤーとサーバーを一緒に更新してください。**

## 導入

既存の BCU フォルダーをバックアップし、**コピーしたフォルダー**で使用してください。
配布 ZIP 内の `bcu-pvp.jar`・`lib`・起動スクリプトを、既存の `assets` と `user` がある
BCU フォルダーに置きます。標準ゲームデータは配布物に同梱していません。
両者で同じオンライン対応版・同じ標準データを使用してください。

JDK/JRE 21 でのビルド・テストを基準にしています。Windows は `start-pvp.bat`、
Linux/macOS は `sh start-pvp.sh` で起動します。
通常の BCU 起動後、メイン画面の「オンライン対戦」を選びます。

## 部屋を作る・参加する

1. 両者が同じルームサーバーのURLと表示名を入力します。
2. 作成者は城の左右を選び、「部屋を作成」を押します。パスワードは空欄なら不要、設定時は8〜128文字です。
3. 入室すると接続画面から**専用の対戦ロビー**に切り替わります。ホストは部屋IDと、設定した場合だけパスワードを伝えます。
4. 参加者は接続画面で部屋IDを入力して「部屋に参加」を押します。3人目は参加できません。
5. ロビーで各自の保存済み編成を選択します。**「編成を編集」**で元のBCUの編成画面を開き、「戻る」で同じロビーへ戻れます。
6. ホストが共通ルールを変更したら**「ルールを適用」**を押します。各プレイヤーは必要に応じて自分の**城体力倍率**を変更して**「自分設定を適用」**を押し、その後それぞれ**「準備完了」**を押します。
7. 全員の準備が揃った時点で編成・ルールを固定し、キャラを自動共有します。共有と検証が成功すると自動的に元のBCU戦闘画面へ進みます。

編成またはルールの変更は、**全員の準備完了を解除**します。相手の変更を確認して、改めて準備完了を押してください。
「準備を解除」で自分の準備完了を取り消せます。ただし全員が揃って共有に移った後は、編成とルールは変更できません。
変更内容と準備状態はサーバーで管理し、古い設定に対する準備完了やゲストによるルール変更は拒否します。
ルームへの入室だけでは、カスタムPackの送信は始まりません。

### ホストが変更できるルール

| 設定 | 内容 |
| --- | --- |
| 城と城の距離 | 実際の城の座標間隔。1000〜24000、初期値4400。戦場の全長は左右余白を加えた「距離＋1600」です。 |
| 背景 | 共通の標準データに含まれる背景から選択します。 |
| BGM | 標準データに含まれる楽曲、または「BGMなし」。戦闘開始時に選択した曲を再生します。 |
| 戦闘特殊機能 | 「にゃんこ砲」「対戦ルーレット」「なし」から選択します。初期値はにゃんこ砲です。 |
| 全員の表示を60FPSに揃える | その試合だけ描画を60FPS設定にします。OFFなら各自の既存設定に従います。 |

各プレイヤーには共通ルールとは別に**自分の城体力倍率**があります。型は `double`、初期値は **20.0倍**です。
0.1〜1000.0の有限値を設定でき、自分側の城HPだけに適用されます。ホストもゲストも自分の倍率を独立して設定でき、
変更すると他の編成・ルール変更と同様に準備完了が解除されます。

ホストは共通ルールの**デバッグモード**をONにできます。ONの試合ではホスト・参加者の両方に
「ルーレットMAX」ボタンを表示し、各自が自分側のルーレットゲージを同期入力で100%へできます。
デバッグモードがOFFの試合ではこの入力は無効です。

背景・BGMはこの版では標準データのみです。カスタム背景・カスタム楽曲の自動転送は含みません。
60FPS固定でも戦闘ロジックは常に30TPSで、各自の保存済みFPS設定を書き換えません。
実際の描画速度はPCの処理性能に依存します。


### 対戦ルーレット

ホストが「対戦ルーレット」を選ぶと、にゃんこ砲の代わりに3DS版の対戦ルーレットを使用します。
抽選は43枠で、3DS実コードから復元した重みと300回シャッフル、隣接する同一結果の修正処理を使います。
ルーレットゲージはにゃんこ砲チャージとは完全に別状態です。Ghidraで3DS実コードを再確認した結果、単純な一定速度ではなく次の加算が重なります。

- **自然増加**: 1秒（BCUでは30 logic tick）ごとに基礎10。
- **城HP補正（FUN_001954d0）**: 自城HP100%で1倍、50%で2倍、0%で5倍。50%の前後を線形補間します。
- **残り時間補正（FUN_001953d0）**: 残り50%以上は1倍、25%以上50%未満は2倍、最後の25%は5倍。3DSは180/300/420/600秒を選択でき、初期ルール値は180秒です。BCUにはまだ制限時間選択がないため、この補正には3DS初期値180秒を使用します。
- **城への被ダメージ（FUN_0019dbc4 / FUN_0023bcc0）**: 前回更新から減った城HPに対して `floor(被ダメージ×3/1000)` を基礎値とし、城HP補正と残り時間補正を掛けて即時加算します。
- **キャラ退場（FUN_002557d8 / FUN_0019f0f0）**: 生産価格と倒れた位置でも加算します。自分のキャラは価格×10/10000、相手キャラは価格×5/10000（基礎値上限250）。位置補正は自城付近1.5倍、中央0.5倍、相手城付近0.1倍で、その後に城HP・残り時間補正を掛けます。

内部には目標ゲージと表示ゲージがあり、表示ゲージは1tickあたり最大50ずつ目標値へ追従します。このため城ダメージやキャラ退場時は自然増加とは異なる速度で増えます。

ゲージが100%になっても**自動では発動しません**。通常の特殊ボタン（キー `2`）を押したときだけルーレット演出を開始し、
約2秒（60 logic tick）回転したあと抽選結果を自動確定して効果を発動します。回転中にもう一度押して演出を短縮することはできません。
戦闘画面右下のにゃんこ砲アイコン・砲チャージ・ルーレット装飾は表示せず、**ゲージだけ**を同じ操作位置に表示します。
100%になるとゲージ上に **TAP!** を表示します。ぷちベビーラッシュ発動中は左上のOnline表示の直下に残り秒数を表示します。
生産短縮・働きネコ仕事効率UP・コストダウン・攻撃力UP・体力UP・移動UPの永続効果は、右上のお金表示の下へ
取得済みアイコンを横並びで表示し、各アイコンに現在のLv1/Lv2/Lv3/MAXを重ねます。
抽選と効果は30TPSの同期状態に含まれるため、描画が30FPS/60FPSで混在しても結果は変わりません。

抽選結果は次の14種類です。

`ふっとばし / いやし / 生産回復 / にゃんこ砲 / 生産短縮 / 働きネコ仕事効率UP / コストダウン / お金MAX / スロウ / ストップ / 攻撃力UP / 体力UP / 移動UP / ぷちベビーラッシュ`

攻撃力・体力・移動速度などの永続強化は**未強化、Lv1、Lv2、Lv3、MAXの5状態**です。
つまり強化を取得して上がる回数は4回で、MAX後に同じ結果を引いてもさらに倍率は増えません。
攻撃力・体力・移動速度の倍率は順に1.5倍、2.5倍、4.5倍、8倍です。
働きネコ仕事効率は100%→150%→200%→300%→500%、コストダウンは1→2→4→8→16段階で打ち止めです。
スロウとストップは3DS実コードと同じ150tickです。

「ぷちベビーラッシュ」は**10秒間だけ再生産クールタイムを0に固定**します。
戦闘ロジックは30TPSなので持続時間は300 logic tickです。働きネコレベルと所持金は変更しません。
通常の「神さま」のベビーラッシュとは別の、通信対戦ルーレット専用効果として扱います。

#### 3DS版の対戦UI素材

対戦ルーレットの表示には、3DS版から取得した元のBCTEX素材をそのままリソースとして保持し、
実行時にCGFX/TXOBテクスチャをデコードします。座標は `BattleCats3DS_analyze/game_files/CSP_Work/csp/images`
にある対応 `imgcut.csv` を読み、Javaコードへ座標を二重定義しません。

現在使用する素材は次のとおりです。

- `ui_battle_multi_icon.bctex`: 14種類のカラー効果アイコン、Lv1/Lv2/Lv3/MAX表示
- `ui_battle_multi_reel.bctex`: 効果名、ルーレットランプ
- `ui_battle_multi_cutin.bctex`: 各効果発動時のカットイン
- `ui_battle_multi.bctex`: 通信対戦用ルーレットランプ等

BCU本来の戦闘背景・城・編成ボタン・所持金などは置き換えません。
3DSの320x240戦闘画面を丸ごと再現するのではなく、元のBCU戦闘UIの上に
ルーレット固有の3DS素材だけを表示します。3DSのRボタン画像はPC版ではRキーがユニット操作と競合するため
操作案内には使わず、PC版の特殊操作キー `2` は従来どおりです。

### 全員が個別に変更できる音量

ロビーの**「自分の音量」**で、BGM・戦闘効果音・操作／生産通知をそれぞれ0〜100%に調整できます。
音声全体のON/OFFも可能です。音量は自分のPCだけに適用され、相手やルームのルールには送信しません。
戦闘中は元の画面上部の**「音量」**ボタンから同じ設定を開けます。設定を開いても対戦は止まりません。
再生中の音にも変更が反映されます。保存にはBCU既存の音量設定と通常の設定保存処理を使います。

相手の生産・生産失敗・働きネコ操作・再生産完了・にゃんこ砲チャージ完了の通知は鳴らしません。
自分側の通知だけを鳴らします。攻撃命中・波動・砲撃など、戦場で実際に起きた共通の効果音は残します。
通知音を聞く側の違いは、戦闘状態・乱数・同期結果には影響しません。

**共有範囲に注意:** 準備完了後、この版は編成が参照するカスタムPackとその依存Packを自動的に
Pack単位で共有します。**そのPackに含まれる未編成のキャラも共有対象**です。
ステージ・リプレイ・楽曲のデータは交換しません。公開したくないキャラがある場合は、
対戦用Packに分けてください。受信側から画像・ステータスを隠す機能はありません。
同じ名前・同じ元Pack IDでも、試合IDと参加者別の名前空間で分離します。
受信Packは読み取り専用で、元の `workspace` や `packs` へ保存・上書きしません。
退出すると一時Packの登録と一時ZIPを削除します。

標準キャラは共通データとして参照します。カスタムキャラが標準アニメを参照する場合は、
元の編集データを置き換えず、共有用の一時スナップショットへ変換します。
4種類・登場アニメ付き5種類・地中移動付き7種類、および魂アニメの構成を維持します。

## 操作とルール

戦闘画面は、元のBCUの `BattleInfoPage`・`BBPainter`・`BBCtrl` を使用します。
独自の単色背景、文字だけの出撃ボタン、上部の独自HP帯、対戦専用FPSプルダウンは廃止しました。
標準データの背景・城・キャラアイコン・再生産ゲージ・所持金・働きネコ・にゃんこ砲をそのまま描画します。
元の「画面拡大」と「1段／2段」の切替、マウスのドラッグ・ホイールによるカメラ操作も使えます。
当たり判定枠・軸線はオンラインの通常描画では表示しません。エディター側の表示設定は変更しません。

操作はBCU既存のキー割当です。2段表示は `Q W E R T / A S D F G` で出撃、
1段表示は `Q W E R T` で表示中の5枠から出撃、`A` または上下ドラッグで段を切り替えます。
`1` は働きネコ、`2` はその部屋の**戦闘特殊機能**です。にゃんこ砲では発射、対戦ルーレットではゲージ100%時にルーレット演出を開始、なしでは無効です。キャラアイコンの右クリック、またはShiftを押しながらの操作で
自動生産を切り替えます。独自UIで使っていた `1〜5 / QWERT`、`F`、`C` にはしていません。
オンラインでは単独の一時停止・コマ送り・倍速・リプレイ切替・コンティニューは無効です。
元の戦闘画面の「戻る」は**部屋を退出せず、現在の対戦を中断して同じ対戦ロビーへ戻ります**。もう一度準備完了すれば同じ部屋で再戦できます。友人用サーバーも維持します。

両者が独立したお金・働きネコ・再生産待ち・特殊機能状態・編成を持ち、同じ戦場で戦います。
城HPが0になった側が敗北し、同一tickに両方0なら引き分けです。戦闘終了後は勝利・敗北・引き分けの結果画面を両者に表示し、**両プレイヤーがOKを押した後**に同じ対戦ロビーへ戻ります。

相手が編成から出撃したユニットを通常撃破すると、倒されたユニットの出撃コストの50%を撃破側のお金へ加算します。
端数は切り捨て、所持金上限を超えません。自爆・魂の自然消滅・相手の攻撃に起因しない消滅・編成コストを持たないユニットは対象外です。

左は敵側の位置ですが、出撃キャラを敵データへ変換せず `EUnit` のまま扱います。
左側の味方キャラは水平反転し、**キャラクター自身が出す**波動・小波動は青い表示になります。
PvPでは初段と後続段の判定幅を両方400、初期オフセットを味方側基準 -67.5 に統一し、
左右の向きだけ反転させています。通常プレイの敵波動500という値は変更しません。
**にゃんこ砲の波動だけは左右とも通常のピンク表示**です。

戦闘は固定30TPSです。表示はホストの60FPS固定がONなら60FPS設定、OFFならBCU既存の30/60FPS設定に従います。
60FPS表示は複製した表示用戦闘状態を使い、表示更新を本体の当たり判定へ戻しません。
入力遅延はサーバー設定の `inputDelayTicks`（3〜8、初期値3）を開始時に合意し、その試合中は固定します。
相手の必須入力がないtickは進めません。
60tickごとに状態ハッシュを照合し、ずれた場合はエラー停止します。
処理落ち・切断・同期ずれを無視して独自に勝敗を進めることはしません。

キャラの能力値を自動的に同じ強さへ調整する機能はありません。
強さ、レベル、お宝、本能・オーブ、コンボは参加者の編成設定に依存します。
初期ルールは城間距離4400（戦場長6000）、各プレイヤーの城体力倍率20.0倍、出撃上限は原則各50です。
倍速・巻き戻し・コンティニュー・スニャイパー・CPUの敵出現はPvPで使用しません。
退出・切断時は試合中止です。再接続、途中復帰、観戦、ランキングはありません。

## 入力内容の保存と再試行

表示名とサーバーアドレスは入力後に自動保存し、次回のオンライン画面・アプリ再起動時に復元します。
保存先は各BCUフォルダーの `user/online-client.properties` です。元の作者名設定は変更しません。
パスワード、部屋ID、UDP鍵、LANの平文通信許可は保存しません。
パスワードなしの部屋は、そのサーバーへ到達できて部屋IDを知っている人が参加できます。
公開サーバーで参加者を限定する場合はパスワードを設定してください。

接続先やパスワードが間違っていた場合は、入力を修正して同じ画面から再試行できます。
接続失敗・部屋からの「退出」では、この画面で起動した友人用サーバーを停止しません。
部屋IDは通信方式や共有状況の表示に切り替わっても残り、「部屋IDをコピー」で取得できます。

## 同じPCで2人分の接続を試す

1. 既存BCUフォルダーを別々のテスト用フォルダーへコピーし、両方を同じ修正版へ更新します。
2. 片方の `start-pvp.bat` を起動してオンライン画面を開き、「このPCで友人用サーバーを起動」を押します。
3. ホストの表示名を入力して「部屋を作成」を押します。パスワードは空欄で構いません。
4. もう片方のBCUを起動し、「このPCのサーバーを使う」を押します。既定の接続先は `ws://127.0.0.1:8766` です。
5. ホストからコピーした部屋IDと別の表示名を入力し、「部屋に参加」を押します。
6. 専用ロビーでそれぞれ編成を選び、ホストがルールを設定します。両方の「準備完了」を押すと、自動共有後に戦闘が始まります。

**同じPCではサーバーを2回起動しないでください。** 2つ目のBCUは既に起動したサーバーへ参加するだけです。
サーバーを起動しただけでは部屋はまだ存在しません。ホストの「部屋を作成」も必要です。
同一PCのloopback接続にはLANの平文通信許可チェックは不要です。
サーバーのTCPポートを変更した場合は両者を同じ値にしてください。`controlPort=0`（自動割当）の場合は、
ホストに表示された接続先URLを手動でコピーしてください。
設定ファイルは作業ディレクトリではなく、BCU本体のフォルダーの `pvp-server.properties` を参照します。

## 友人同士で遊ぶ最短手順

### ゲーム内でサーバーを起動

オンライン画面の **「このPCで友人用サーバーを起動」** を押します。
`pvp-server.properties` があれば読み込み、なければ初期値で起動します。
起動後は自分のサーバーURLが自動入力され、LAN/VPNの接続先候補を選んでコピーできます。

ホスト自身は `ws://127.0.0.1:8766`、友人はホストのLAN/VPNのIPを指定します。
**友人のPCからホストの127.0.0.1には接続できません。** 部屋IDと、設定した場合だけパスワードも別途伝えてください。
「退出」は現在の部屋だけを終了し、組み込みサーバーは維持します。
「戻る」でオンライン画面から離れるか、アプリを閉じると組み込みサーバーも停止し、そこで中継している他の部屋も終了します。
複数の対戦を継続運用する場合は、次の専用サーバーを使ってください。

### 専用サーバー

Windowsは `start-pvp-server.bat` をダブルクリック、Linux/macOSは次を実行します。

```sh
sh start-pvp-server.sh
```

サーバーだけならJava 21・配布JAR・lib・設定ファイル・起動スクリプトで動きます。
ゲームのアセット、画面、データベース、アカウント登録は不要です。
終了はCtrl+C。部屋の一時ファイルとUDPセッションを破棄します。
別設定を渡す場合は `sh start-pvp-server.sh /path/to/settings.properties`、設定確認は
`sh start-pvp-server.sh --check-config` です。旧 `start-relay` は位置引数型の互換ランチャーとして残しています。

### 接続の選び方

同じLAN内なら、例として `ws://192.168.1.10:8766` を使用し、
クライアントの **「信頼するLAN／暗号化VPNでWSを許可（公開回線はWSS）」** をチェックします。
別の場所の友人とは、暗号化されたプライベートVPN上のホストIPで同様に接続できます。
Tailscaleなどを使う場合も、インストール・共有・アクセス許可は利用者側で設定してください。

**プライベートIPであること自体は暗号化を意味しません。** WSでは部屋パスワードとUDP鍵も平文で運ばれるので、
信頼できないLANや公開回線には使用しないでください。UDPのAES-GCMだけでは、平文WSで渡した鍵の盗聴を防げません。
公開回線では制御通信に必ずWSSを使用してください。

アプリはルーター、Windows Firewall、VPN、TLS証明書を自動変更しません。
ファイアウォールでは必要な友人/LAN/VPNの送信元だけに **TCP 8766・UDP 8767** を許可します。
通常の家庭内サーバーをインターネットへ直接公開する場合は、サーバー側のNAT・ファイアウォール設定が必要です。
UDPが利用できなくても、制御用WebSocketに接続できれば対戦開始前に自動的にWSへフォールバックします。

## サーバー設定

```properties
bind=0.0.0.0
controlPort=8766
udpPort=8767
udpEnabled=true
udpHost=
maxRooms=32
maxConnections=128
maxParticipantsPerRoom=8
roomIdleMinutes=10
bundleMaxMiB=32
inputDelayTicks=3
friendsMode=true
```

`bind=0.0.0.0` は全IPv4インターフェースで待ち受けます。LAN/VPNの特定IPへ限定することもできます。
`udpHost` が空ならクライアントはサーバーURLと同じホストへUDPを送ります。
WSSのリバースプロキシ/CDNとUDPの宛先が異なる場合は、**直接UDPが到達するIPまたはホスト名**を設定してください。
通常のWSSリバースプロキシはUDPを中継しません。UDPポート番号はサーバーが案内するため、
ポート転送を使う場合は内外で同じUDPポート番号にしてください。
`udpEnabled=false` は全員がWSで対戦する診断用設定です。
`friendsMode` は起動時の運用案内を切り替えます。認証や暗号化を弱めるスイッチではありません。

**`maxParticipantsPerRoom=8` は通信コアの技術上限であり、8人対戦を有効にしません。**
現在選べる `DUEL_1V1` は2人までです。将来の2v2等は新しいGameModeと戦闘ルールの実装が別途必要です。
1つのサーバーで複数の1v1部屋を中継できます。

### WSSリバースプロキシ例

次の例ではサーバーを `bind=0.0.0.0` で起動し、TCP 8766は外部へ公開せずNginxからのみ到達可能にし、
UDP 8767だけ必要な送信元へ別途許可します。TCPをループバックに限定する場合は、
UDPも同じ `bind` に従う点に注意してください。UDP不要なら `udpEnabled=false` にできます。

```nginx
server {
    listen 443 ssl;
    server_name pvp.example.com;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:8766;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 90s;
        proxy_send_timeout 90s;
        proxy_buffering off;
    }
}
```

パスワード試行制限は接続元IP単位です。リバースプロキシ経由では1つのIPに集約されます。
大規模公開用の認証/プロキシ設計にはしていません。友人用でもパスワードや共有データは適切に管理してください。

## 通信と再送

部屋・パスワード・キャラデータ・準備・結果はWebSocket/WSS、戦闘入力と確定フレーム・チェックポイントはUDP優先です。
キャラ共有はルーム専用の一時ディスクキャッシュを使い、同じSHA-256のデータを重複アップロードしません。
通信側は参加者IDを使い、1v1の左右位置への変換は専用アダプターに分離しています。

UDPは最大1200バイト、AES-256-GCM、方向別鍵・nonce、64パケットの再送攻撃拒否窓を持ちます。
受信ACK＋32bitの選択ACKでRTT・揺れ・欠損を見積もり、表示します。これらは通信診断値であり、画面に反映されるまでの遅延とは異なります。
通常は最新を含む4tick分を冗長送信し、欠けた古いtickは明示要求でも再送します。
既に受理した入力を変更したり、再送によって自動生産ボタンを再度トグルしたりしません。
通信タイマーは描画/戦闘の進行とは独立しているため、入力待ち中も再送が続きます。
通信混雑・ACK途絶時には再送頻度を下げ、無制限な再送ループにしません。

UDPプローブは最大4回（250ms間隔）、1500msで応答がなければ試合開始前にWSへ切り替えます。
片方UDP・片方WSでも動作します。UDPが250ms停滞した場合はWSを緊急の再送経路として使いますが、
これは試合中の恒久的な通信方式切替ではありません。**認証済みUDPを3秒受信しなければ試合を安全に中止**します。
必須入力の欠損を「入力なし」と見なして先へ進める処理、ロールバック、再接続は実装していません。

## 安全制限・エラー

最大32部屋、128接続、1送信元IPあたり1分12回の入室/作成試行。
共有ZIPは各32MiBまで、展開後64MiBまで、4096ファイルまで。
PNGは1辺8192まで、各画像1677万画素まで、合計3355万画素まで。
アニメのパーツ数・キーフレーム数にも上限があります。
巨大Packや循環依存Packは無理に読み込まず拒否します。

`VERSION` は対応版不一致、`ASSETS` は標準データ不一致、`AUTH` は部屋ID/パスワード不一致、
`FULL` は満員、`DESYNC` は戦闘状態の不一致です。接続・入室エラー後は入力を修正して再試行できます。
進行中の試合が中止された場合は新しい部屋で対戦してください。
待機部屋は設定時間（初期10分）、共有/準備中の無進捗は120秒、戦闘無進捗は30秒で終了します。
UDP_ACTIVEで認証済みUDPが3秒届かない場合は、それより早く `UDP_TIMEOUT` になります。

## ビルドとテスト

```sh
git clone --recurse-submodules --branch feature/online-pvp-30tps https://github.com/SSSCFW/BCU-java-PC.git
cd BCU-java-PC
mvn -B clean verify dependency:copy-dependencies -DoutputDirectory=target/lib
bash tools/package-pvp.sh
```

出力は `target/bcu-pvp-portable.zip` です。
Java21、Maven3.9系、依存ライブラリ取得用の通信が必要です。
テストだけを省く場合は `-DskipTests=true` を明示します。
Gradleでは `./gradlew check` がPvP統合テストを含みます。

`src/main/java/common` は元のコミットに固定したサブモジュールです。
変更した共通クラスは `src/pvp/java/common` のソースオーバーレイとして保持し、
Maven/Gradleが生成するソースツリーへ重ねてコンパイルします。
**元のsrc/main/javaだけを直接コンパイルするとPvPの変更は入りません。**
IDEから実行する場合も、Maven/Gradleの生成ソースを利用してください。

自動テストでは、生成した小さな画像・アニメを使って実際のBCU戦闘エンジンを動かします。
UDP/UDP・UDP/WS・WS/UDP・WS/WS、欠損/重複/順序入れ替え、650ms途絶と緊急再送、
3秒途絶での安全中止、テスト専用8人モードの通信・データ共有、専用/組み込み共通の起動処理を確認します。
さらに別々のJVMによる接続、同名・同IDで異なるキャラの交換、30/60FPS混在、
実ダメージ、通常/小波動の左右判定、表示コピーの独立性、同期ずれ停止を検証します。
標準ゲームデータ一式や全ユーザー作成Packを使った検証ではありません。
実インターネットでの通信品質、全特殊能力の組み合わせ、JOGL環境ごとの差異は、
配布版を使った追加実機テストが必要です。

## 配布CI

MavenとGradleの両方が成功したfeatureブランチのビルドだけを `pvp-dev` へ公開します。
Actionsには配布フォルダーを保存し、Releaseジョブで再構成したZIPがMavenジョブで作ったZIPと
**バイト単位のSHA-256まで一致すること**を確認してから公開します。
古いビルドが遅れて終了しても、新しいfeatureブランチのReleaseを上書きしません。
PRビルドは検証のみで、Releaseの公開権限を使いません。
